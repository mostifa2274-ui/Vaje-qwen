# Human Accessibility Validation Matrix

Automated DOM/browser checks remain mandatory, but they are not an accessibility-conformance claim. This gate closes only after hands-on assistive-technology testing.

## Required journeys

A human tester must complete the core learning path on each relevant surface: teach, written preparation, listening preparation, story/reading comprehension, Smart Review, book/cumulative exam, glossary, pronunciation practice, backup/settings, and the Today/Journey/Library home.

| Surface | Required validation |
| --- | --- |
| Android | TalkBack with current Chrome: full core journey |
| iPhone/iPad | VoiceOver with current Safari: full core journey |
| Desktop | Keyboard-only plus one mainstream screen reader |
| Zoom | 200% browser zoom with no lost controls or task-breaking horizontal scroll |
| Text size | Large mobile accessibility text where supported |
| Motion | Reduced-motion preference |
| Contrast | Forced/high-contrast mode where supported |
| Audio conflict | Screen-reader speech and course narration remain operable |
| Microphone | permission denied, allowed, revoked, pending-permission navigation, unsupported browser |
| Offline | previously loaded core journey with assistive technology enabled |

## Evidence required

For each run record device, OS, browser, assistive-technology version, tester, date, result, and issue/evidence references. Final sign-off records reviewer, role, date and scope. A screenshot alone is not sufficient. Automated tests cannot populate or approve this ledger.
