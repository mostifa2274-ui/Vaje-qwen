# Research and evidence

Browse current primary/authoritative sources when a decision depends on learning science, accessibility standards, language pedagogy, browser/platform behavior, or another changing external fact.

## Evidence hierarchy

Prefer:
1. systematic reviews/meta-analyses
2. strong peer-reviewed studies relevant to the population/task
3. standards and authoritative institutional guidance
4. well-documented engineering/product evidence
5. expert commentary only when stronger evidence is unavailable

## Translate evidence carefully

Check:
- learner population and proficiency
- L1/L2 context
- learning target
- immediate vs delayed outcome
- dosage/spacing
- whether app behavior actually matches the studied intervention

Do not cite generic memory research as direct proof of this product.

## Claim vocabulary

Use:
- **research-informed** — design follows relevant literature
- **internally verified** — software/content gates passed
- **validated in a learner study** — only with actual qualifying study evidence
- **best-in-class** — only with explicit, bounded comparative evidence

At skill creation, repository `research/status.json` reported `protocol-ready-not-run` and `research-informed-not-empirically-validated`. Re-read the current file every time a claim depends on it.

## Policy calibration

If evidence motivates changing a threshold/interval:
- document rationale
- update canonical policy source
- update tests/validators
- distinguish evidence-backed vs heuristic values
- preserve any external calibration gate
